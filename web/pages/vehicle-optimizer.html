what does this do exactly?

vehicle files contain a lot of redundant and unused XML attributes. removing those typically cuts 13–40% of the file size, reducing the amount of data that needs to be sent, processed, and synchronized. these savings compound in multiplayer, improving fps, tps, and desync.

Specifically
  • removes empty <logic_slots> elements
  • removes empty <slot/> elements
  • removes ac="" from components that don't use additive color
  • removes r="" from components that look the same regardless of rotation
  • removes r="" when the default rotation can be safely omitted
  • removes sc="" when it only contains the face count rather than actual face colors
  • removes bc="" when face colors are present and the base color can be safely omitted
  • removes default names and descriptions

how does this work?

the file is processed entirely in your browser with a single-pass scanner. it reads through the xml once and applies each rule as it goes. nothing from the vehicle is ever sent anywhere.

and this is provably safe: the parser runs in the browser, is opensource and you can see every network request the page makes along with exactly what js is running in your browser's developer tools.

What exactly is actually sent on every usage, the following is sent: 
 {
   "type": "tool_process",
   "tool": "vehicle_optimizer",
   "input_bytes": _,
   "output_bytes": _,
   "processing_ms": _,
   "blocks_changed": _,
   "blocks_preserved": _
  }

this data is timestamped and stored server-side to track usage. it contains no vehicle data or IP address.
